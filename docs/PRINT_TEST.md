# 58 mm 打印测试

此阶段使用 Windows 打印驱动和 Electron `webContents.print()`。厂商 SDK 仍是后备路线。小票依据 `assets/pos sample.png` 的布局制作，正式石珠线稿、文案与映射尚未提供。

1. 在 Windows“打印机和扫描仪”确认 POS58 Printer 在线，装入 58 mm 纸。关闭驱动额外页眉、页脚和缩放。程序按票面实际内容计算纸张长度，不再把内容压进固定高度。
2. 在项目根目录运行 `npm run build`，再运行 `npm start`；或运行 `npm run dev:electron`。完成昵称和公历日期输入，在结果页查看同模板预览。
3. 点击“打印测试票”一次。等待“已提交到 Windows 打印系统”或错误反馈。不要把“已提交”当作实体打印完成。结果不明时先检查纸张和 Windows 队列。
4. 检查纸宽、页数、底部留白、中文、线稿、横线、条码及裁切。扫描 Code 128，要求与票面 `TEST-` 编号逐字一致。记录驱动型号、连接方式和实际结果。

浏览器预览不调用打印机。开发测试票的条码带 `TEST-` 前缀且标注“不可兑换”；当前不可用于正式核销。`userData/print-jobs` 只保留最小任务元数据，不保存参与者表单。测试任务在提交前落盘、同一结果页重复点击不会重复提交，超时/崩溃/断连后不自动重放。返回首页、闲置重置或主窗口重载会清除内存中的票面快照。打印进行时暂不执行普通闲置重置。

纸卷宽 58 mm；当前 POS58 驱动报告的页面及可打印区域宽约 48 mm。因此屏幕预览保留 58 mm 纸面和两侧各 5 mm 空白，实际打印交给驱动的是中间 48 mm 内容区，避免重复留白与右侧裁切。纸长按模板内容高度加 3 mm 余量生成。驱动对自定义纸长、定位和裁切的行为仍须在换纸后实机验证。当前 Electron 打印回调只表示向 Windows 提交任务，不能证明实体打印完成；即使机器缺纸，Windows 也可能继续显示“正常”。若需要程序准确报告缺纸、打印完成等设备状态，应接入开发包的自动回传接口（C# 示例中有 `CP_PRINTERSTATUS_ERROR_NOPAPER`）。

开发运行时可按 `F12` 或 `Ctrl+Shift+I` 打开主窗口的前端 DevTools，在 Console 查看 React 页面错误。Electron 主进程的错误写入启动它的 PowerShell 终端；`npm start` 加载 `dist/`，修改代码后先执行 `npm run build` 并重启程序。`npm run dev:electron` 会同时启动 Vite 和 Electron，用于热更新调试。打包后的 Kiosk 不提供 DevTools 快捷键。
