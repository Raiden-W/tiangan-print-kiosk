# 58 mm 打印测试

P03 的 PRINT THE RECEIPT 进入 P04 并提交一次打印。屏幕小票和实际纸票共用 FortuneTicket 组件，使用正式字体、日干中英文、黑色元素 PNG 和启动时加载的本地寓意。无条码及测试标记。

1. 确认 Windows 中 POS58 Printer 在线，装入 58 mm 纸；名称中的空格不影响匹配。
2. 配置 DeepSeek 密钥，运行 build + start 或 dev:electron，完成所有输入后生成结果。浏览器只有固定演示，不调用打印机。
3. 点击打印一次，等待提交反馈。已提交仅表示 Windows 接收，不证明实体出纸。
4. 核对只打印一张、有效纸宽、中文、黑色元素图标、虚线、留白和裁切。无条码扫码测试。
5. 缺打印机可检查连接后返回结果页重试；已提交、失败或结果不明的已准备任务不自动重放，不新增补打入口。

页面不再显示设备枚举调试信息，无法读取列表与列表中缺少目标设备分别提示。浏览器仅预览。历史上 Windows 和 Electron 曾枚举到 `POS58 Printer`（驱动 POS58，端口 CP001），不代表当前物理纸张状态。

P04 以固定遮罩与平移表现吐纸：初始仅露出 24px 下边缘，入页 700ms 后开始，3000ms linear 完成。屏幕动画与硬件状态独立，更新状态不重播；实体票不带这段动画、遮罩或背景纸纹。打印页面先提交 React 视图，再等待字体和全部图像解码完成，才通知主进程可以打印。

纸卷宽 58 mm，沿用现有 POS58 驱动的约 48 mm 有效内容宽。仅实体票在底部横线后放置 5 mm 空白占位块，移除该横线原本的底部外边距。实体票原有 5 mm 底部内边距保留，纸长按渲染高度加 3 mm 余量生成。屏幕小票不渲染占位块。实际尾端走纸长度须在 Windows 打印机设置中配置；页面留白与驱动进纸长度叠加后再检查裁切位置。

打印仅接受主进程当前结果 ID，票面来自已校验 AI 快照，不能由渲染进程提供任意票面或按日期重新计算。任务在提交前记录到 userData/print-jobs；只写任务 ID、时间、版本、状态、尝试次数，不写个人信息。清理会话清除内存票面，打印过程中暂停普通闲置重置。

返回成功不代表纸张传感器状态。当前未接入厂商缺纸或打印完成回传。现场需实机验收，本轮自动化使用模拟打印回调，不向实体打印机提交任务。

P04 目前仅保留“返回首页”。本轮 UI 验证阻断打印入口，没有向硬件发送任务；屏幕纸张动效与实体出纸情况无关联。
