# 中国地点索引

出生地点与现居地共用 `content/locations.json`。数据打包到应用，搜索和选择均离线完成；没有引入地点组件库、在线 API 运行依赖或数据库。

## 来源与版本

- 主要来源：中国国家地名信息库的公开行政区划搜索接口：<https://dmfw.mca.gov.cn/9095/xzqh/getList?maxLevel=2>，服务说明：<https://dmfw.mca.gov.cn/interface.html>。
- 抓取日期：2026-10-22。接口默认返回最新数据，但未给出明确年版；不将抓取日期宣传为法定区划的生效日期。
- 原始响应的 SHA-256 记录在 JSON 元数据中，便于追溯快照。
- 接口为台湾省返回“资料暂缺”，其22县市按政府公开名录补充：<https://www.president.gov.tw/Page/106>。显示使用简体名称，保留部分繁体别名供搜索；TW-前缀是应用内部稳定标识，非虚构的官方代码。

## 覆盖与层级

当前只开放中国，34个省级选项、394个可选城市／地区项：

| 类别 | 数量 | 选择方式 |
| --- | --- | --- |
| 地级行政区 | 333 | 293个地级市、30个自治州、7个地区、3个盟，保留完整名称 |
| 直辖市 | 4 | 北京、天津、上海、重庆，城市级选自身，不将市辖区/县当作城市 |
| 省/自治区直辖县级地区 | 33 | 济源、仙桃、潜江、天门、神农架、海南直辖地区、新疆兵团城市等直接可选；不伪装成地级市 |
| 香港与澳门 | 2 | 各提供自身作为地点，不增加区县层级 |
| 台湾地区县市 | 22 | 在台湾省下提供相应县市，类型单独标记，不声称均为地级市 |

内地索引使用服务返回代码的前6位。`type` 保留上述差异；province/city ID 与父级关系一起校验。由于参与者出生年份可能较早，本版提供当前名称索引，不做历史行政区划还原。

## 表单行为

- 两处均可按名称、代码或“省份 城市”组合关键词搜索，点选结果会填入完整层级。
- 上级变动必须清空下级，出生地点变动也清空旧的时区建议；选择城市后再建议时区。
- 地点仍为选填；一旦填写，需选完整且上下级匹配的地点，也可使用清空按钮全部清除。
- 内地建议 Asia/Shanghai；港、澳、台分别使用 Asia/Hong_Kong、Asia/Macau、Asia/Taipei。仍允许手动改动，所有地点/时区信息都不参与日干计算。

## 维护

仅由维护者在明确需要更新时运行：

```sh
node scripts/update-china-locations.mjs
npm test
npm run lint
npm run build
```

该脚本是唯一需要联网的地点数据维护步骤，不在启动或构建时自动运行。写入前检查覆盖、代码和重复 ID；行政层级或总量变化时先人工复核。更新后检查 JSON 差异，重新确认台湾县市及特殊地区。只有用户明确要求才 push。

## 未来扩展

继续采用按国家筛选、审核后随包发布的离线数据；不同国家的州/省、郡、城市层级不完全相同，不强行逐项等同中国地级市。

- `country-state-city` 提供 JS 查询接口，适合快速验证全球列表。当前仓库标为 GPL-3.0：<https://github.com/harpreetkhalsagtbit/country-state-city>。
- Countries States Cities Database 可按国家提取 JSON，便于仅引入目标国家。当前数据许可为 ODbL-1.0，需保留署名并核对数据派生要求：<https://github.com/dr5hn/countries-states-cities-database>。
- GeoNames 提供按国家下载和地名 API，适合更广的城市/别名/坐标/时区数据，但需筛选地名类型与行政层级：<https://www.geonames.org/export/>。
- 在线搜索可评估 Google Places Autocomplete；中国行政区域查询可评估高德。需要网络、Key、配额和相应条款，不把服务结果未经核对直接当成可永久打包的离线行政区数据库。
- 多时区国家应按城市对应的 IANA 时区处理；不能仅按国家套一个时区。仍保持其与日干算法分离。
